# Простая инструкция

## 1. Что запускать

В этом архиве есть магазин, отдельный импорт Excel и самостоятельный редактор.
Это обычные окна Python/Tkinter, браузер не нужен. Магазину и импортёру нужен
запущенный PostgreSQL. Редактор работает без базы.

Из корня проекта:

| Команда | Что открывает |
| --- | --- |
| `python main.py` | Полное приложение |
| `python import_db.py` | Импорт Excel без входа в магазин |
| `python Excel_Preparation/main.py` | Отдельный редактор Excel |

## 2. Первый запуск: Mac или Linux

Распакуй архив. Открой терминал в папке проекта, где находятся `main.py`
и `requirements.txt`. Например:

```bash
cd ~/Downloads/Chudo_Obuv_Project
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m tkinter
```

Последняя команда открывает небольшое тестовое окно. Закрой его.
Если возникла ошибка `_tkinter`, нужен Tkinter именно для версии твоего Python.
На Ubuntu/Debian: `sudo apt install python3-tk python3-venv`.
На Mac с Homebrew проверь `python --version`; пакет Tkinter должен совпадать
с версией Python. Например, для Python 3.14: `brew install python-tk@3.14`.
После смены Python пересоздай окружение и установи зависимости заново.

Теперь запусти PostgreSQL и заполни файл подключения, как описано ниже.
Если база пустая, сначала выполни `python import_db.py` и импортируй данные.
После этого запусти:

```bash
python main.py
```

## 3. Windows

Открой PowerShell в папке проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python import_db.py
python main.py
```

Если PowerShell не разрешает активацию, можно запускать напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

PostgreSQL должен быть установлен и запущен и на Windows тоже.

## 4. Подключение к PostgreSQL

Единственный файл подключения — **`postgres_connection.json` в корне проекта**.
Его читают магазин и импортёр. Подключение в окнах не редактируется.
Сохрани файл и перезапусти открытые окна после смены параметров.

Пример для PostgreSQL на этом компьютере:

```json
{
  "host": "localhost",
  "port": "5432",
  "database": "excel_data",
  "user": "postgres",
  "password": "твой_пароль",
  "schema": "public",
  "active_tables": null
}
```

| Поле | Что означает |
| --- | --- |
| host | Адрес сервера; localhost — этот компьютер |
| port | Порт PostgreSQL, обычно 5432 |
| database | Название уже созданной базы |
| user | Пользователь PostgreSQL |
| password | Его пароль |
| schema | Схема с таблицами, обычно public |
| active_tables | null — читать все таблицы схемы; список — только указанные |

JSON должен оставаться правильным: строки в двойных кавычках, запятые между
полями, без комментариев и без запятой после последнего поля.

**Обычный PostgreSQL без Docker.** Запусти установленный сервер. Если база
ещё не создана, например:

```bash
createdb -h localhost -U postgres excel_data
```

Пользователь может называться иначе: укажи реальное имя своего пользователя
PostgreSQL. На Mac это иногда имя пользователя компьютера.
Для PostgreSQL через Homebrew служба запускается командой
`brew services start имя_службы`; установленные службы покажет `brew services list`.
На Linux системный PostgreSQL обычно запускается через
`sudo systemctl start postgresql`.

Импортёр создаёт таблицы в выбранной базе, сам PostgreSQL и базу не устанавливает.
Если таблицы уже заполнены, импорт не нужен — сразу запускай магазин.

**Docker.** Открой Docker Desktop на Mac/Windows или запусти Docker на Linux.
В корне проекта:

```bash
docker compose up -d
```

В приложенном примере: база `excel_data`, пользователь `postgres`, пароль
`postgres`, порт `5432`. Эти параметры укажи в JSON.
Если обычный PostgreSQL уже занимает порт 5432, используй один сервер
или настрой для контейнера другой свободный порт.

**В этом Docker-примере данные временные:** остановка или перезапуск
контейнера очищает базу. После этого нужен повторный импорт.
У обычного PostgreSQL данные сохраняются после перезапуска сервера.

## 5. Следующие запуски

В терминале из папки проекта:

```bash
source .venv/bin/activate
python main.py
```

На Windows используй свою команду активации из раздела 3.
PostgreSQL должен работать. Если Docker остановлен, сначала
`docker compose up -d`, затем импорт данных и запуск приложения.
Закрытие окна приложения при работающем сервере данные не удаляет.

## 6. Импорт Excel

```bash
python import_db.py
```

1. Нажми «Выбрать файлы». Можно выбрать несколько Excel.
2. Если это результат редактора, выбери все XLSX из одной подготовленной папки.
   `import_profile.json` оставь рядом с ними: он загрузится автоматически.
3. Нажми «Проверить Excel» и посмотри результат.
4. Нажми «Импортировать» и дождись сообщения о завершении.
5. Закрой импортёр и запусти `python main.py`.

**«Пересоздать таблицы» заменяет выбранные таблицы и их данные.** Без флажка
строки добавляются: повторяющиеся ключи не становятся обновлением записей.
Старые таблицы, которых нет среди новых файлов, автоматически не удаляются.
Для другой темы удобно создать отдельную базу или схему.

Кнопка «Правила редактора» позволяет вручную выбрать профиль. Профиль должен
соответствовать выбранным Excel. Если написано «Эти Excel-файлы не входят
в выбранный профиль», проверь папку и имена файлов в профиле.

## 7. Редактор Excel

```bash
python Excel_Preparation/main.py
```

Редактор можно перенести отдельно вместе с его папкой. Тогда создай в ней
окружение, установи её `requirements.txt` и запускай `python main.py`.

| Действие | Что делает |
| --- | --- |
| «1. Открыть» | Читает новые Excel |
| «2. Разделить» | Выносит повторяющиеся поля в отдельную таблицу с ID |
| «3. Связать» | Создаёт отношения и получает ID по совпадению названий |
| «4. Сохранить» | Создаёт новую папку с Excel, профилем и проектом редактора |
| «Файл → Открыть проект» | Продолжает ранее сохранённую работу |

**Для продолжения работы открывай `normalizer_project.json`.** Он хранит
данные, имена, ключи и отношения. Повторное открытие только выгруженных XLSX
не восстанавливает старые связи. 
При создании связи слева выбирай таблицу, в которой нужна ссылка; справа —
таблицу со справочником. Если уже записаны ID, используй режим «ID».
Если записаны названия или ФИО, используй «Название / ФИО».
Например, `stock_items.product_name → products.product_name` заполняет
`product_id`; `stock_items.size → sizes.size` заполняет `size_id`.

Совпадения должны быть однозначными. Родительский ID должен быть уникальным
и заполненным. Размер обуви 20 не обязан иметь ID 20: это разные значения.
Проверить связи можно через «Связи → Все отношения» и «Проверить структуру».

Само количество внешних ключей не доказывает 3НФ. Для 3НФ разделяют сущности
и проверяют зависимости полей. Справочник производителя хранит его название,
а товар хранит ссылку `manufacturer_id`.

## 8. Работа с магазином

Вход — по логину из таблицы пользователей, без пароля.
Гость просматривает каталог. Покупатель выбирает товар, размер и количество,
добавляет позиции в корзину, оформляет заказ и видит свои заказы.

Менеджер и администратор могут работать с заказами клиентов. Администратор
также меняет дату, удаляет позиции и уменьшает количество. Скидка 25%
применяется к товарам без заказов за предыдущий календарный месяц.
Данные меняются в PostgreSQL. Кнопка «Настройка данных» выбирает,
какие таблицы и колонки читает приложение. Кнопка «Авто» помогает начать.

## 9. Где менять оформление и поведение

В цельной версии меняй файлы в корне проекта.
В модульной версии полное приложение находится в `Module_4_Orders`;
его настройки и фото находятся внутри этой папки.

| Что изменить | Где |
| --- | --- |
| Цвета | `design.py`: `COLORS` |
| Шрифт | `design.py`: `FONT_FAMILY`, `FONT_SIZES` |
| Название и подписи | `design.py`: `APP_TITLE`, `BRAND_NAME`, `TEXTS` |
| Карточки списком или плиткой | `PRODUCT_CARD_LAYOUT = "list"` или `"grid"` |
| Поля карточки | `CARD_FIELDS`, `DETAIL_FIELDS` |
| Колонки заказов | `ORDER_COLUMNS` |
| Размеры окна и отступы | `WINDOW`, `SPACING` |
| Таблицы и поля БД | `config.py`: `DATABASE_MAPPINGS` или «Настройка данных» |
| Поля из справочников | `config.py`: `DATABASE_LOOKUPS` |
| Скидка | `NEW_PRODUCT_DISCOUNT = "0.25"`; "0" отключает её |
| Размеры | `PRODUCT_VARIANTS_ENABLED`; False — товар без размеров |
| Остатки | `STOCK_MODE`: auto, separate, product или none |
| Заказы | `ORDERS_ENABLED`; False — только каталог |

Фото товаров положи в `images/`. В поле изображения товара в БД укажи имя
файла, например `shoe.png`. Логотип — `assets/logo.png`; путь меняется через
`LOGO_PATH` в `design.py`. Если в `settings.json` указан `images_folder`,
он имеет приоритет над стандартной папкой фото.

После изменения настроек Python перезапускай приложение.
Другая тема может требовать других сопоставлений и отключения размеров.
Импорт поддерживает разное число файлов, листов и столбцов, но назначение
неизвестных полей нужно выбрать: универсальный импорт не определяет сам
смысл произвольной базы и требования нового задания.

Настройки импорта: корневой `config.py`.

| Правило импорта | Для чего |
| --- | --- |
| IMPORT_TABLE_RULES | Имена таблиц/колонок, типы и первичные ключи |
| IMPORT_FOREIGN_KEYS | Явные отношения |
| IMPORT_REFERENCE_RULES | Получение ID по тексту |
| IMPORT_AUTO_FOREIGN_KEYS | Автоматические предположения связей |
| IMPORT_HEADER_ROWS | Строка заголовков по файлам и листам |

Профиль редактора при импорте задаёт структуру вместо этих правил.

## 10. Посмотреть базу и сохранить копию

Обычный PostgreSQL:

```bash
psql -h localhost -U postgres -d excel_data
```

Docker:

```bash
docker compose exec postgres psql -U postgres -d excel_data
```

В консоли PostgreSQL: `\dt public.*` — таблицы; `\d public.orders` — колонки,
первичный ключ и связи заказов; `\q` — выйти.

Резервная копия обычной БД:

```bash
pg_dump -h localhost -U postgres -d excel_data --no-owner --no-privileges -f backup.sql
```

Для Docker:

```bash
docker compose exec -T postgres pg_dump -U postgres -d excel_data --no-owner --no-privileges > backup.sql
```

Применить SQL отношений к обычному PostgreSQL:

```bash
psql -h localhost -U postgres -d excel_data -v ON_ERROR_STOP=1 -f table_relations.sql
```

Для Docker:

```bash
docker compose exec -T postgres psql -U postgres -d excel_data -v ON_ERROR_STOP=1 < table_relations.sql
```

Пути и параметры замени своими. SQL отношений бери от своей структуры,
например из сохранённой папки редактора. Если импортировал правильный профиль,
связи уже создаются при импорте. Шаблон обувной схемы не применяй к другой теме.

## 11. Если что-то не работает

| Проблема | Что сделать |
| --- | --- |
| Нет `.venv/bin/activate` | Создай окружение в текущей папке |
| Нет `_tkinter` | Установи Tkinter для своей версии Python и пересоздай окружение |
| Нет библиотеки | Активируй окружение и установи `requirements.txt` |
| Ошибка подключения | Проверь сервер и корневой `postgres_connection.json` |
| Нет товаров или пользователя | Проверь выбранную базу, таблицы, active_tables и «Настройку данных» |
| Нет фото | Проверь имя файла, поле изображения и папку фото |
| Остатки не читаются | Проверь ссылки остатков на товар и размер и выбранные поля |
| Профиль не принимает Excel | Используй Excel и профиль из одной выгрузки |
| При повторном редактировании пропали связи | Открой normalizer_project.json через «Открыть проект» |
| Данные пропали после перезапуска Docker | Импортируй заново; приложенный контейнер хранит данные временно |

Проверка источника данных без вывода пароля:

```bash
python tools/inspect_database.py
```

Проверить рабочий сценарий можно так: войти, открыть товар, оформить заказ,
посмотреть его состав и остаток. Дополнительно есть тесты:
`python -m unittest discover -s tests`. В модульной версии запускай эту команду
в папке нужного модуля. Проверки PostgreSQL требуют отдельной тестовой базы
через `CHUDO_TEST_DSN`; без неё часть тестов пропускается.

## 12. Аналитика и модульная версия

Цельная версия содержит одно полное приложение. Его экраны разделены
на файлы внутри `interface/`, работа с БД — внутри `storage/`, импорт — `excel_importer/`.
Редактор находится в `Excel_Preparation`, аналитика — в `Reports`.
Пример ER-диаграммы: `docs/ERD_module_1.pdf`.
Для сдачи по пяти этапам используй отдельный модульный архив.

Аналитике нужны четыре CSV из задания. Из папки `Reports`:

```bash
python main.py "/путь/к/папке/CSV"
```

Названия файлов и колонок задаются в её `config.py`. Примеры в тестах не
заменяют реальные исходные CSV задания.


## 13. Расположение файлов

Команды запуска остались прежними: `python main.py` и `python import_db.py`.
Настройки подключения — в корневом `postgres_connection.json`, оформление —
в `design.py`, правила поведения и соответствия полей — в `config.py`.

| Папка или файл | Назначение |
| --- | --- |
| `interface/application.py` | Главное окно и переключение экранов |
| `interface/catalog_view.py` | Каталог |
| `interface/customer_views.py` | Вход, товар и корзина |
| `interface/order_views.py` | Работа с заказами |
| `interface/widgets.py` | Общие элементы интерфейса |
| `interface/formatting.py` | Вывод подписей, цен и полей |
| `interface/data_mapping.py` | Окно выбора таблиц и колонок |
| `interface/import_window.py` | Окно импорта; только в полной версии и модуле 1 |
| `storage/repository.py` | Чтение и запись PostgreSQL |
| `storage/order_operations.py` | Заказы, остатки и скидки |
| `storage/schema_adapter.py` | Подстройка к структуре таблиц |
| `storage/connection.py` | Чтение файла подключения |
| `excel_importer/` | Чтение Excel и создание таблиц |
| `tools/inspect_database.py` | Проверка подключения и выбранных таблиц |
| `Excel_Preparation/` | Самостоятельный редактор Excel |

В модульной версии папки интерфейса и БД находятся внутри соответствующего
этапа. Для разработки полной версии используй `Module_4_Orders`.
У редактора остаётся собственное внутреннее устройство, потому что он
запускается как самостоятельное приложение.
