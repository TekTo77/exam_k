# Редактор Excel перед импортом в БД

Отдельное обычное окно на Python и Tkinter. Магазин, PostgreSQL и Docker
для запуска не нужны. Читает таблицы, помогает вынести справочники,
переименовать поля и заменить текстовые ссылки на ID.

## Запуск

Mac / Linux, терминал в `Excel_Preparation`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

Windows:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

Если Tkinter не найден, проверь `python -m tkinter`. Установи Tkinter для той
же версии Python. Для Homebrew нужен соответствующий `python-tk@X.Y`.
Если PowerShell запрещает активацию, запускай через `.\.venv\Scripts\python.exe`.

## Четыре кнопки

| Кнопка | Что делает |
| --- | --- |
| **1. Открыть** | Читает один или несколько Excel. Слева появятся таблицы |
| **2. Разделить** | Выносит отмеченные повторяющиеся поля в новую таблицу |
| **3. Связать** | Находит запись в готовой таблице и записывает её ID |
| **4. Сохранить** | Создаёт отдельную папку с подготовленными XLSX и отношениями |

Исходные файлы не переписываются. Слева выбираешь таблицу и колонки;
справа видны первые 200 строк. Двойной щелчок по ячейке открывает правку.
Все строки сохраняются, ограничение 200 касается только предпросмотра.
`★` — первичный ключ, `→` — внешний ключ. Отменить шаг: **Ctrl/Cmd+Z**.

Имена приводятся к латинице: известные слова переводятся, неизвестные
русские названия транслитерируются. Значения ячеек на английский не
переводятся. Если имя получилось непонятным, поменяй его через
**Таблица → Переименовать**.

## Пример 1: производитель повторяется в товарах

1. Открой файл товаров, выбери его слева.
2. Нажми «Разделить» и отметь поле производителя. Если страна зависит от
   производителя и должна храниться там же, отметь также страну.
3. Проверь предложенное имя новой таблицы и ID. При необходимости поменяй
   их в дополнительных параметрах.
4. Подтверди: появится таблица уникальных производителей. В товарах вместо
   вынесенных полей будет их `manufacturer_id`.

Это операция для новой таблицы. Если производители уже существуют отдельным
файлом с собственными ID, используй «Связать», чтобы сохранить эти ID.

## Пример 2: связать заказы с пользователями по ФИО

Открой одновременно файлы пользователей и заказов. В пользователях должен
быть уникальный ID; существующие корректные ID сохраняются. При отсутствии
ключа редактор добавит новый ID строки.

1. Нажми «Связать».
2. Слева выбери `orders`, ниже — поле с ФИО заказа.
3. Справа выбери `users`, ниже — **«ФИО целиком»**, если ФИО там хранится
   в фамилии, имени и отчестве отдельно. Если всё в одной колонке, выбери её.
4. Посмотри примеры: `Иванов Иван Сергеевич → user_id = 17`.
5. Нажми «Создать связь».

В заказах создастся или заполнится **реальный ID из users**, например 17,
а не номер строки заказа. Программа не связывает людей по случайному
совпадению фамилии. Два одинаковых ФИО или неизвестный человек показываются
как проблема. Сначала исправь данные; либо явно разреши оставить `NULL`.

Уже заполненный правильный ID сохраняется. Конфликт с найденным человеком
не переписывается без включения дополнительного параметра.

Исходный текст при связывании готовых таблиц сохраняется для проверки.
Когда проверишь ID и текст больше не нужен, удали его через
**Таблица → Удалить колонку**. Для 3НФ не стоит хранить имя клиента в заказе,
если оно полностью определяется `user_id`. Учти: удалённое поле не нужно
оставлять в будущих сопоставлениях приложения.

## Если несколько отношений или уже есть ID

Создавай отношения по одному: заказ → пользователь, позиция → заказ,
позиция → товар, товар → производитель. Одна таблица может иметь несколько
ссылок, это нормально. Последняя связь не удаляет предыдущие.

Если в заказе уже записан ID пользователя, выбери этот столбец слева,
`user_id` справа и режим **ID**. Существующие текстовые коды `001`, UUID и
числовые ID поддерживаются; для текстового кода `001` и `1` — разные записи.

Для составного ключа используй **Связи → Составной ключ**. Число полей с
обеих сторон должно совпадать. Сначала назначь родительский ключ через
**Таблица → Первичный ключ**. Самоссылки или сложные составные отношения
проверяй вручную; простое окно предназначено для понятной связи двух таблиц.

**Связи → Все отношения** показывает созданные ссылки и позволяет убрать
ненужную. **Связи → Проверить структуру** находит ошибки и даёт подсказки.

## Другие действия

- **Файл → Параметры чтения:** номер строки заголовков, добавление новых
  файлов к открытым, схема PostgreSQL для сохраняемого SQL.
- **Файл → Сохранить проект:** сохранить JSON и продолжить позже.
- **Файл → Открыть проект:** вернуть таблицы, типы, ключи и связи.
- **Таблица:** имена, PK, тип колонки, добавление/удаление колонок и строк.
- **Правка → Отменить шаг:** вернуть предыдущее состояние.

Закрытие после успешно сохранённого результата не требует повторного
подтверждения «несохранённых» изменений. После новой правки предупреждение
снова появится.

## Что делать после сохранения

Появится новая папка `prepared_...` с файлами:

| Файл | Зачем |
| --- | --- |
| `.xlsx` | Подготовленные таблицы с ID |
| `import_profile.json` | Имена, PK, типы и FK для импортёра |
| `table_relations.sql` | Только отношения для этой структуры |
| `normalizer_project.json` | Снова открыть в редакторе |
| `import_settings.txt` | Необязательная текстовая копия правил |

**Следующий шаг:** открой модуль 1 основного проекта, запусти `python main.py`,
выбери все XLSX из этой папки и импортируй. Профиль рядом подхватится сам.
Не смешивай файлы разных подготовленных папок с одним профилем.

Импортёр с профилем уже создаёт отношения; второй запуск SQL не обязателен.
Если нужна отдельная команда для PostgreSQL без Docker:

```bash
psql -h localhost -U postgres -d excel_data -v ON_ERROR_STOP=1 -f /путь/к/prepared/table_relations.sql
```

Подставь имя своей базы и пользователя. Этот SQL относится к сохранённой
структуре и предполагает, что таблицы уже импортированы.

## Универсальность и 3НФ

Можно открывать разное число XLSX, XLS, XLSB, XLSM, ODS, листов и колонок.
Нужны табличные листы с одной строкой заголовков. Непустые и пустые
именованные столбцы сохраняются. Числовые/текстовые ID, даты, десятичные
значения и явные составные ключи проверяются при подготовке.

Редактор работает **со значениями**: оформление исходной книги, макросы и
формулы не переносятся. Формулы сначала рассчитай и сохрани в Excel или
LibreOffice. Новый результат сохраняется в XLSX. Сложный отчёт с объединёнными
ячейками и несколькими таблицами на одном листе сначала приведи к таблице.

3НФ нельзя доказать по внешнему виду Excel. Надо понимать зависимости:
какая колонка определяет другие. Редактор помогает выполнить выбранное
разбиение и проверить ключи, но не решает смысловые зависимости за человека.
Уникальные идентификаторы и отсутствие потерянных ссылок сами по себе ещё
не означают 3НФ.

## Код и проверка

`main.py` — запуск; `excelprep/ui.py` — основное окно и действия;
`excelprep/links.py` — связь готовых таблиц; `excelprep/model.py` — изменения
таблиц и сохранение; `design.py` — цвета и шрифт; `config.py` — дополнительные
форматы дат. Магазин не требуется ни как установленный пакет, ни как соседняя
папка.

```bash
python -m unittest discover -s tests
```

Обычные проверки работают с зависимостями редактора. Для дополнительной
проверки реального PostgreSQL установи `psycopg[binary]` и задай отдельную
тестовую БД в `CHUDO_TEST_DSN`. Проверка окна требует графический экран.
При отсутствии условий интеграционные тесты пропускаются.
