# Чудо Обувь — модуль 2: каталог

Python + Tkinter + PostgreSQL. На этом этапе сразу открывается каталог:
фото, категория, производство, состав, итоговая цена со скидкой и суммарный
остаток. Малый остаток подсвечивается. Вход, фильтры и оформление заказов
появляются в следующем этапе.

## Подключение и запуск

Инструкция для всего проекта — `INSTRUCTION.md` в общей папке.
Подключение берётся только из общего `postgres_connection.json` в корне
модульной поставки. В окне параметры базы не редактируются.
При отдельном переносе модуля положи этот JSON рядом с его `main.py`.

PostgreSQL должен быть запущен. Установи зависимости из `requirements.txt`,
запусти `python main.py`. Для импорта используй модуль 1.
Ни импорт, ни приложение не переписывают файл подключения.
`active_tables: null` разрешает читать все таблицы выбранной схемы.

## Как устроены файлы

| Файл | Назначение |
| --- | --- |
| `interface/application.py` | Переключение экранов, текущий пользователь и корзина |
| `interface/catalog_view.py` | Каталог, поиск и фильтр |
| `interface/customer_views.py` | Вход, карточка товара, корзина и подтверждение |
| `interface/order_views.py` | Список, состав и редактирование заказов |
| `interface/components/product_tile.py` | Отрисовка одной карточки |
| `storage/repository.py` | Чтение PostgreSQL и сопоставление полей |
| `storage/order_operations.py` | Заказы, права, остатки и календарная скидка |
| `storage/schema_adapter.py` | Необязательные размеры, справочники и другая тема |
| `design.py` | Вид интерфейса |
| `config.py` | Названия таблиц и правила приложения |
| `module_settings.py` | Номер этапа задания |

Код экранов общий по устройству между этапами, но копии независимы.
Основные доработки делай в модуле 4; переноси их в ранние этапы, только если
это нужно для задания. Для запуска соответствующего этапа достаточно его
собственной папки.

## Оформление и фото

В `design.py`: `COLORS`, `FONT_FAMILY`, `FONT_SIZES` — цвета и шрифт;
`TEXTS`, `APP_TITLE`, `BRAND_NAME` — подписи; `SPACING`, `WINDOW` — размеры.
`PRODUCT_CARD_LAYOUT = "list"` включает строки, `"grid"` — плитки.
`CARD_FIELDS`, `DETAIL_FIELDS` меняют вывод полей; `ORDER_COLUMNS` — колонки
таблиц заказов. Это настройки разработчика; переключателя вида в окне нет.

Фото положи в `images/`; в соответствующем поле БД укажи имя, например
`shoe.png`. Имена файлов должны совпадать с БД. Логотип — `LOGO_PATH`, иконка —
`WINDOW_ICON_PATH`. `None` убирает их. Путь к картинке-заглушке — `PLACEHOLDER_PATH`.

Папка фото задаётся `DEFAULT_IMAGES_FOLDER`. Если в `settings.json` уже есть
`images_folder`, он имеет приоритет: поменяй или удали эту настройку.
Файлы PNG, JPEG и другие поддерживаемые Pillow форматы обрабатываются тем
же способом. Подготовленные фото и логотип из исходного архива сохранены.

## Другая БД и другая тема

«Настройка данных…» меняет только сопоставления. Она не переименовывает
таблицы PostgreSQL. Кнопка «Авто» выбирает предположения; проверь их перед
сохранением. Старые сопоставления лежат в `settings.json`.

Пример `config.py` для книг:

```python
DATABASE_MAPPINGS = {
    "products": {"table": "books", "columns": {
        "product_id": "isbn", "product_name": "title", "price": "cost",
        "image_path": "cover_file", "category": "genre",
    }},
    "users": {"table": "readers", "columns": {
        "user_id": "reader_id", "login": "login", "last_name": "surname",
    }},
}
PRODUCT_VARIANTS_ENABLED = False
STOCK_MODE = "none"
```

Это пример, а не готовые настройки для каждой базы. Укажи реальные имена.
`STOCK_MODE` может быть `"auto"`, `"separate"`, `"product"`, `"none"`.
`ORDERS_ENABLED = False` оставляет один каталог. Если сохраняешь заказы,
сопоставь также `orders`, `order_items` и пользователя по реальному ID.
`INSERT_DEFAULTS` задаёт свои дополнительные обязательные поля при вставке.

Справочник производителя можно вывести так:

```python
DATABASE_LOOKUPS = {"products": {"manufacturer": {
    "column": "manufacturer_id", "table": "manufacturers",
    "key": "manufacturer_id", "value": "manufacturer_name",
}}}
```

С учётом реальных внешних ключей некоторые справочники определяются сами.
Для своего поля, например автора, добавь в `EXTRA_PRODUCT_FIELDS`:

```python
EXTRA_PRODUCT_FIELDS = {
    "author": {"aliases": ("author", "writer", "автор"), "label": "Автор"},
}
```

И строку карточки в `design.py`, например в `CARD_FIELDS`:

```python
{"template": "Автор: {author}", "fields": ("author",), "hide_empty": True}
```

Добавляй её внутрь существующего списка/кортежа, не стирай остальные строки.
Для другой роли: `ROLE_ALIASES = {"директор": "Администратор"}`.
Для другого формата даты настрой `DATE_INPUT_FORMATS`.

## Скидка и целостность

`NEW_PRODUCT_DISCOUNT = "0.25"` даёт 25% товару без заказов за прошлый
**календарный** месяц. `"0"` отключает скидку. Проверяется история всей модели,
а не отдельного размера. В заказе сохраняется цена на дату оформления.
Изменение сегодняшней цены не переписывает прежние заказы.

`schema.sql` и `table_relations.sql` — пример стандартной обувной структуры.
Для другой базы используй SQL отношений, полученный редактором, или свои
реальные названия. Пустая схема не является дампом данных. Не запускай
шаблон обуви поверх уже подготовленной базы другой темы.

Удобная проверка: `python tools/inspect_database.py`. Если нет товаров или
логин не найден, проверь базу, схему, `active_tables` и «Настройку данных».
Если фотографии нет, проверь имя файла и папку. Если `_tkinter` отсутствует,
установи Tkinter для версии своего Python. Подробнее — корневой README.
