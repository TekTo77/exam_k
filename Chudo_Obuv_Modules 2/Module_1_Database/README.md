# Чудо Обувь — модуль 1: база данных

Python + Tkinter + PostgreSQL. Здесь чтение Excel, создание таблиц, загрузка
данных, подготовленная ER-диаграмма и пример SQL для задания.
Редактора Excel в этой папке нет: он поставляется отдельным проектом.

## Запуск

Из всей поставки: `python import_db.py` в корне после установки зависимостей.
Для отдельного использования открой терминал в этой папке:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

На Windows: `py -3 -m venv .venv`, затем `.\.venv\Scripts\Activate.ps1`.
PostgreSQL должен быть запущен, база должна уже существовать. Импортёр
создаёт таблицы, а не сервер PostgreSQL. Для Docker есть `docker-compose.yml`.
Учебная база в нём очищается при остановке/перезапуске контейнера.

## Как импортировать

1. «Выбрать файлы»: один или несколько Excel с табличными листами.
2. Подключение берётся из общего `postgres_connection.json` в корне поставки.
   При отдельном переносе модуля положи JSON рядом с его `main.py`.
3. «Проверить Excel»: посмотри таблицы, ключи и предупреждения.
4. «Импортировать»: дождись сообщения об успешной загрузке.

Если файлы получены из редактора, выбирай все XLSX из одной сохранённой
папки. Лежащий там `import_profile.json` подхватится автоматически.
При необходимости выбери его кнопкой «Правила редактора». Его параметры
имеют приоритет над старыми правилами `config.py`, строка заголовков для
подготовленных файлов всегда 1.

«Пересоздать таблицы» заменяет выбранные таблицы и их данные. Без флажка
строки добавляются: нужны стабильные уникальные ключи. Импорт файла с
повторяющимися сгенерированными ID не становится обновлением автоматически.
Перед пересозданием нужных данных сделай резервную копию.

Импортёр не сохраняет и не меняет подключение. Настрой его в JSON
до запуска; уже открытое приложение после импорта перезапусти.

## Ключи и произвольные Excel

Поддерживаются XLSX, XLS, XLSB, XLSM, ODS через библиотеки чтения. Число файлов,
листов и столбцов может быть разным. Нужна одна строка заголовков и строки
записей. Отчёты с объединёнными ячейками и несколькими отдельными таблицами
на одном листе сначала подготовь.

Если естественного ключа нет, добавляется ID строки. Автоматическое определение
связей — предположение по именам ID и значениям; неоднозначную связь программа
не должна выбирать наугад. Проверяй журнал или задавай правила явно.
Для задания с латинскими именами сначала подготовь Excel отдельным редактором.
Сырые неизвестные русские имена импортёр может сохранить русскими.

Настройки `config.py`:

- `IMPORT_TABLE_RULES` — имена таблиц/колонок, первичные ключи и типы.
- `IMPORT_FOREIGN_KEYS` — явно заданные связи.
- `IMPORT_REFERENCE_RULES` — получение ID по тексту, например ФИО.
- `IMPORT_AUTO_FOREIGN_KEYS` — включить/выключить автоматические предположения.
- `IMPORT_HEADER_ROWS` — свои строки заголовков для файлов и листов.
- `DATE_INPUT_FORMATS` — дополнительные даты.

Пример для авторов и книг:

```python
IMPORT_TABLE_RULES = {
    "авторы": {"table": "authors", "columns": {"Код": "author_id"},
               "primary_key": "author_id"},
    "книги": {"table": "books", "columns": {"Код": "book_id", "Автор": "author_id"},
              "primary_key": "book_id"},
}
IMPORT_FOREIGN_KEYS = (("books", "author_id", "authors", "author_id"),)
```

Здесь `Автор` уже содержит ID. Для текстовых названий нужна замена на ID в
редакторе или правило `IMPORT_REFERENCE_RULES`. Само объявление внешнего
ключа не заменяет текст числом. Настройки из профиля редактора уже содержат
все явно сделанные отношения.

`IMPORT_HEADER_ROWS = {"books.xlsx": 3}` задаёт заголовки в строке 3;
для разных листов: `{"books.xlsx": {"Каталог": 3, "Авторы": 1}}`.

## SQL и ER-диаграмма

- `docs/ERD_module_1.pdf` — диаграмма семи сущностей обувного задания.
- `schema.sql` — пример пустой структуры с PK, FK и ограничениями.
- `table_relations.sql` — только связи стандартной схемы.

Эти файлы — обувной пример. Для другой структуры возьми отношения из
редактора. Импортёр не применяет `schema.sql` автоматически и не заставляет
произвольные Excel превращаться в семь обувных таблиц.

Шаблон структуры можно применить к отдельной пустой базе:

```bash
psql -h localhost -U postgres -d excel_data -v ON_ERROR_STOP=1 -f schema.sql
```

Не запускай его поверх уже существующих одноимённых таблиц другой структуры.
Для обычного импорта достаточно кнопки: она строит структуру из Excel.
«Сохранить schema.sql» в окне сохраняет структуру прочитанных файлов;
это не дамп данных.

Для сдачи SQL с реальными данными после импорта сделай `pg_dump`; команда
есть в корневом README. Если структура изменилась относительно диаграммы,
обнови ER-диаграмму под свою фактическую базу.

## Импорт без окна

База и схема берутся из того же JSON, параметры подключения в команду не передаются.

```bash
python -m excel_importer.cli /путь/к/файлам
```

Профиль рядом с файлами подхватится и здесь. Можно указать
`--profile /путь/import_profile.json`, `--append`,
`--sql-out schema.sql`, `--header-row 3` для неподготовленных файлов.

## Проверка

`python -m unittest discover -s tests`. PostgreSQL-тест требует отдельную
тестовую базу через `CHUDO_TEST_DSN`; проверка окна — графический экран.
Сам сервер, ресурсы Excel заказчика и «Автотест» в проект не включены.
