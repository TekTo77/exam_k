# Чудо Обувь — модуль 5: аналитика

Python + pandas. Здесь расчёты по заданию 5.1–5.6; приложение магазина и
PostgreSQL не нужны. Исходные CSV из приложения 4 не были переданы,
поэтому реальные ответы появятся после добавления этих файлов.

## Запуск

Создай окружение и установи `requirements.txt`, как в корневом README.
Положи четыре CSV в папку `data/` рядом с этим файлом:

- `Sessions_analytics.csv`
- `Orders_analytics.csv`
- `Order_items_analytics.csv`
- `Shoe_models_analytics.csv`

```bash
python main.py
```

Можно указать другую папку и сохранить результат:

```bash
python main.py /путь/к/CSV --save answers.json
```

Терминал покажет шесть ответов. При равном максимуме перечисляются все
победители. При отсутствии данных для медианы или корреляции программа
так и сообщает. Значения не придумываются.

## Что рассчитывается

| Задание | Расчёт |
| --- | --- |
| 5.1 | Уникальные покупатели / уникальные посетители по типу устройства |
| 5.2 | Медиана минут между первой сессией и первой завершённой покупкой, если прошло до 7 суток |
| 5.3 | Февральское удержание январской когорты по каналу первой сессии |
| 5.4 | Число заказов после удаления выбросов стоимости по правилу 1,5 IQR |
| 5.5 | Корреляция Пирсона между скидкой и количеством |
| 5.6 | Категория с максимальным суммарным количеством проданных пар |

Период по умолчанию: с 01.01.2026 включительно до 01.04.2026, правая граница
не включается. Учитываются завершённые заказы. Отменённые заказы исключаются.
Даты с часовым поясом сравниваются в UTC; даты без пояса считаются UTC.
Если в реальных CSV принят другой пояс, сначала приведи время согласованно.

Стоимость позиции берётся из её итоговой суммы, если такая колонка есть.
Иначе: `quantity * unit_price`. Второй раз скидка не вычитается. Если в твоём
файле `price` — цена до скидки, а итог хранится отдельно, явно сопоставь
`items.amount` на эту итоговую колонку.

Корреляция по умолчанию считается по позициям, если скидка находится в
`items`. Если она находится только в `orders`, количество суммируется по
заказу. Это зависит от структуры реальных CSV. Через `CORRELATION_LEVEL`
можно явно выбрать `"items"` или `"orders"`; проверь соответствие данным
приложения 4 перед сдачей ответа.

## Свои названия CSV и колонок

В `config.py`: `FILES` — названия четырёх файлов; `COLUMNS` — соответствия.
Например:

```python
COLUMNS = {
    "sessions": {"started": "visit_time"},
    "orders": {"created": "date_order", "discount": "sale_percent"},
    "items": {"model": "shoe_id", "price": "cost_per_pair"},
    "models": {"id": "shoe_id", "category": "shoe_category"},
}
```

Неизвестные или неоднозначные имена не угадываются: программа попросит
сопоставление. Автоматические варианты полей находятся в `ALIASES` файла
`analytics.py`. CSV читаются как текст, чтобы не потерять коды `001`.
Разделитель определяется автоматически; кодировка UTF-8, с запасным чтением
Windows-1251. Числа ожидаются с точкой.

## Проверка

```bash
python -m unittest discover -s tests
```

Проверки используют отдельные искусственные примеры; это не исходные
данные заказчика. Выдачу реальных ответов надо проверить с настоящими CSV.
